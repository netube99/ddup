# 目录与文件归属

[文档入口](index.md) · [开发指南](development.md) · [架构](../ARCHITECTURE.md)

文件按用途归属，不能只凭“旧、未被 Git 跟踪或内容相似”删除。

## 文档层级

| 位置 | 内容 | 维护规则 |
| --- | --- | --- |
| README | 项目定位、首次运行 | 保持短，只给最常见路径 |
| AGENTS | agent 全局边界、分层禁令、维护门禁 | 不复写完整接口表，链到专题文档 |
| ARCHITECTURE | 模块关系、生命周期、跨模块不变式 | 机制顺序或契约变化时更新 |
| docs/index | 按任务导航、设计信息地图、skill 路由 | 新文档必须从这里可达 |
| docs 专题 | 后端、因子、策略、研究、CLI、结果、ML、实盘 | 接口的唯一权威说明，保留边界与例子 |
| docs/review_protocol | 当前审查规则与分级 | 与 backlog 门禁 CLI 同步 |
| docs/review_backlog.yaml | 未决和已关闭发现 | 由 review_gate 维护，保留历史 ID |
| docs/reviews/YYYY-MM-DD | 当日范围、发现、证据和限制 | 归档事实；不随当前文档整理论断改写 |
| .agents/skills | 任务触发和操作流程 | 只保留决策、危险点、输出/停止条件；细节链到专题 |

`docs/devlog/` 是本机私有研究笔记，不随仓库分发。清理它时保留能复现实验的数字、配置、
结果库指针和假设，但不必保留逐轮讨论、旧 API 或已被当前实现取代的实施清单。

## 代码与资产

| 位置 | 应放内容 | 维护约定 |
| --- | --- | --- |
| `btcore/` | 引擎、数据接口、因子/撮合/ML/database 基础设施 | 遵循 AGENTS 的依赖方向 |
| `adapters/` | 后端实现与可分发模板 | 本机配置和模板分别维护 |
| `factors/` | 用户因子库与模板 | YAML 是用户数据，不按生成物清理 |
| `strategies/examples/` | 教学策略 | 与演练命令保持一致 |
| `strategies/selected/`、`exploring/`、`archive/` | 精选、研究中和历史策略 | 本机资产；迁移前核对路径和模型引用 |
| `research/` | 可导入的研究库 | 不放 CLI 或一次性结果 |
| `scripts/` | CLI、检查、基准和诊断入口 | 现有命令路径保持稳定 |
| `scripts/diagnostics/` | 绑定审查日期的独立复现脚本 | 记录运行命令、依赖和适用范围 |
| `tests/` | 单元、集成、回归和不变量测试及 fixtures | review 回归是长期测试，不是临时文档 |
| `results/` | 本机回测库、报告与研究状态 | 不是再生缓存；不批量改基线 |
| `live/` | 实盘账本、券商输入与操作单 | 真实账户资产；研究/排错用副本 |
| `logs/`、`archive/` | 运行日志与本机历史产物 | 按具体用途判断，不因被忽略自动删除 |

## 清理规则

- 可再生缓存：项目内 `__pycache__/`、`*.pyc`、`.pytest_cache/`、`.ruff_cache/`、
  `.coverage*`、`htmlcov/`、`coverage.xml`。
- `.venv/` 与环境、`.git/` 与版本历史不进入文档缓存清理。
- 删除源码、测试或配置前检查调用点与业务身份；相同内容可能服务不同策略或历史复现。
- 历史审查迁移时保留 ID、严重级、独立期望、原始数值、复现入口和限制。当前处置看
  backlog；历史记录只有新证据才能重开。
- 私有策略、模型、结果库、研究状态、日志和实盘账本不因 `.gitignore` 或重复相似被批量清理。
