状态：已实施（2026-10-24，交付记录见
[reviews/2026-10-24/live_v2_delivery.md](reviews/2026-10-24/live_v2_delivery.md)）。
本文件仍是验收基准；实施中的语义细化以交付记录为准。

基线：`4f727e2c4fd65c5af2854d41a0455732b9b998fb`；启动时工作区干净。
用户确认旧实盘系统从未使用，允许破坏性修改接口及数据模型；不需要兼容旧账本。

## 1. 目标与边界

交付本地、单账户、A 股个股、日频手动执行工作台。完整闭环：
账户导入/接管 → 账户核验 → 策略启用 → 只读预览 → 接受计划 → 记录执行状态/成交
→ 再次对账 → 从实际状态继续。后期 AI 使用相同结构化接口。

保留现有因子、模型声明、策略钩子、provider 因果约束和回测语义。
不做真实券商连接、网页前端、盘中行情引擎、多账户资金分配或全仓重构。
不承诺模拟条件单与所有券商等价；不支持的执行语义必须明确拒绝或转人工提示。
无需迁移旧实盘库；新 schema 必须有版本和身份，旧库只读识别后清楚拒绝，不写坏旧文件。
使用现有 DuckDB 依赖、单进程串行写事务；不引入消息队列/服务集群。

## 2. 模块与依赖

- `research/live_account.py`：账户领域类型、独立账本 schema、导入去重、快照、现金流、差异、管理政策、审计事件。不得依赖 Engine。
- `research/live_plan.py`：决策到执行计划、预算和数量、容差、依赖、条件转换、计划及订单状态机、成交关联。依赖账户模块，不依赖 CLI。
- `research/live_strategy.py`：策略启用/版本、provider/Engine 适配、因果计算、状态恢复、实际账户注入。不修改用户策略以适应实盘。
- `research/live.py`：薄的应用服务/公共门面；替换旧实现，不再维护平行的 V1 写账主路径。
- `scripts/live.py`：输入解析、服务调用、人类表格或 JSON；业务规则留在 research。
- `scripts/live_e2e_check.py`：离线模拟完整流程与异常恢复；不删除用户路径，使用自身临时目录。

公共账户模型、状态和异常名由账户阶段一次定义，随后组件复用。必要共享类型放账户模块，
不得以反向 import 打破分层。模块名可由主控批准调整，但上述职责不能退化为一个大函数。

## 3. 账户事实与记账契约

### 3.1 快照与来源

持久保存完整券商快照（as_of、来源、导入身份、现金余额/可用现金、全量持仓与可卖数量）。
导入不依赖行情已更新；行情缺失只阻止相关估值/策略建议，不阻止保存真实账户事实。
同一来源身份同内容重入幂等；同身份不同内容报冲突，不静默覆盖。原始输入或规范化原文保留。
缺 holdings 不等于空仓，必需字段缺失拒绝；合法空仓需显式空列表。
价格/数量/费用/日期验证明确，拒绝 NaN/Inf/布尔伪整数/负股数、负可用资金、可卖数大于持仓。
资金输入明确 CNY 和收盘时点；只有 cash 的简化输入按余额=可用现金、冻结=0 解释并文档化。

最新确认快照是操作基础；历史持仓推导是审计与差异来源，不是强迫用户补完所有历史的前提。
导入保存候选快照及差异；正常匹配自动确认；差异需明确分类/接管确认，确认前不偷换正式状态。
接管允许真实持仓与历史不同，但留下原因、前后值及历史不完整标识，不伪造成交。
status 查询确认快照与未决差异，sync/import 成功确认后立即可见，无需运行策略。

### 3.2 成交与修正

成交字段包括 account/source/trade_id（或明确的人工事件 ID）、时间/顺序、symbol、side、quantity、price、fees、可选 plan/order 关联。
幂等以稳定身份判定，不能按价格股数内容去重；不同 ID 的相同成交都保留。
无券商 ID 时用稳定 import batch+row 身份或显式人工事件 ID，并防止同批重入。
更正用引用原记录的 correction/void 或版本化修正事件，禁止悄悄改历史/伪造反向成交。
成交与账户状态投影、订单已成交量更新在同一事务；拒绝超卖/超计划成交等矛盾而保留可诊断输入。
真实外部成交允许不关联计划，标为 external/manual；不得强行猜交易原因。

### 3.3 现金流与权益

分开 deposit、withdrawal、fee、dividend、tax、explicit_adjustment；不再自动把一切差额记无类别 ADJUST。
差额金额小也不能自动当作外部入金；可设置分位数值容忍，但不能改变财务分类。
账户现金余额、可用于新增委托的资金、待执行预算分别表达。
投资 PnL = 期末权益 - 期初权益 - 净外部出入金；费用/税费扣盈亏，分红计投资收益。
必须有独立数值样本。快照接管若差额无法分类，收益状态标 incomplete，不能伪造精确收益率。
本轮无需改 btcore.stats 的无外部现金流口径：实盘自己提供明确的现金流调整日序列或收益视图；
不可将含出入金的原始权益直接宣称可无差别交给旧回测报表。
市场公司行为用于预期差异与策略价格锚点调整；券商实际股数/现金为确认事实，不能重复入账。

### 3.4 持仓管理政策

至少 managed / exit_only / observe（人工保留）三种；observe 仍计资产和资金占用，策略不能动它。
保留期限及原因可记录；过期后明确恢复规则。账户成本与策略 entry_anchor 分开。
中途接管可不提供完整历史。管理持仓的入场日期/锚点未知时显式要求补锚点或保持 observe；
不能静默编造日期、holding_days 或 trailing high。错误只定位相关持仓/决策，不损坏其余事实。

## 4. 策略会话与决策

启用记录 effective_date、配置/源码/模型身份、接管政策和初始锚点；正式版本固定。
试算另一策略不改变正式会话。更换策略需新 activation，不能用新策略偷偷重写旧决策。
行情 warmup 可以早于启用日；账户/策略交易状态不能因此虚构早于启用的交易。
所有 buy/sell/sell_shares/buy_weights/target_value/buy_conditions/持仓条件均须有明确支持路径或拒绝信息。
特别是 target_value 不得消失；target=0 明确清仓，未列出的持仓保持不动。

预览只读，不能改变正式快照、策略状态、调仓计数、计划版本或历史报表。
允许在内存工作副本中计算。接收计划时一次性记录决策输入版本、输出与必要的状态提交。
重启恢复必须与不中断运行相同。优先显式状态记录；若任意旧 Python 策略不能安全序列化，
允许从 activation 边界按已记录的实际账户/决策事件确定性重放，记录其限制和成本，
不得 pickle 整个对象或重跑全账户生命史来替代正式启用边界。
缺执行日可以跨日恢复；策略调度与未成交计划各自有状态，未执行不被伪装为执行完成。
因果检查：改变未来数据不改变过去决策。缺行情/过期账户/未知锚点必须有可操作错误。

## 5. 计划、预算与执行

### 5.1 计划内容

不可变 plan_id/revision、账户快照版本、策略版本、signal_date/trade_date/expiry、动作、理由、预算、参考价、数量、依赖和警告。
新计划替代旧计划要明确 supersede；已有活动委托/unknown 结果不能被当作从未执行。
同一快照/策略/参数重复接受不能制造重复有效计划或重复预算预留。
快照或策略发生变化后，旧预览必须拒绝直接接受，要求重算。
支持接受、跳过（原因）、过期、取消、部分完成、完成；部分成交后剩余量计算正确。
账户 facts 不因接受计划而提前改变；预算预留与实际现金分别记录。

### 5.2 分配与容差

同批顺序预算递减；合计现有现金支出+费用缓冲不超过可用现金减已有预留。
未来卖出回款只作为依赖条件，未确认成交前不能解锁相应买单。
target_value 统一转差额；目标权重/名单不能重复计已有仓位。A 股买入整手与清仓零股明确。
价格、股数、可卖数、持仓政策、最大资金/仓位、费用缓冲都是确定性校验。
提供 min_trade_amount、position_tolerance、price_deviation_limit、cash_buffer 等少量可解释设置；
容差不用于掩盖账户矛盾。配置命名由实现最终确定并同步唯一接口文档。

### 5.3 条件与执行适配

固定止损/止盈可翻译为价格条件及有效期；移动止盈按本项目最高收盘锚点生成固定日价，
不声称等同于券商盘中 trailing。已满足 ML_EXIT 等非价格退出转换为明确操作或明确 unsupported。
保留条件优先级/互斥组；同票开盘卖出后应撤销/缩减相关保护单，不输出可重复卖全仓的执行方案。
不支持的自定义 handler 不能被压成空价格貌似成功。
手动执行器、离线模拟执行器共享接口。模拟执行器用于拒单、部分成交、超时未知、重连查询测试。
订单状态至少 planned/submitted/partial/filled/cancelled/rejected/unknown；合法转换明确。
每次提交有稳定 client_order_id；unknown 需查询核验，不能盲目重发；重启保持该状态。
本轮不实现真实 API、浏览器交易、凭据配置或 AI 自主下单。
