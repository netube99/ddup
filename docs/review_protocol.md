# 开发收敛协议（维护期）

本协议展开 AGENTS.md「开发收敛协议」。目标是把已确认的错误计算排除，并停止无边界的
检查与改动。一次审查不承诺穷尽所有缺陷；完成条件是约定范围的证据足够、阻塞项已处置、
对应验收通过。最近基线见 `review_record_20261012.md`。

## 范围与证据

审查开始前记录代码 commit、工作区 diff、使用路径、覆盖模块与不覆盖的范围、验收命令。
普通修改只检查 diff 和直接影响的调用链。全量检查须有用户明确请求或共用计算链路失效的
证据；冷却期外也不自动安排全量检查。每轮修复后只验收修复 diff。

发现须有已写契约、准确代码位置、支持路径上的复现、实际结果、独立期望值和影响。
未复现的推测放在审查记录的“待验证”，不计入缺陷数，不据此改代码。
“特定输入触发”不意味着非阻塞：若输入受支持且能产生错误现金、股数、收益、成交或前视，
仍是 P0/P1。旧 backlog 的等级不是免责依据。

| 级别 | 含义 | 处置 |
| --- | --- | --- |
| P0 | 已复现的数据损坏或核心计算错误，影响范围广 | 阻塞：最小修复并验收，或用户显式 waive |
| P1 | 支持路径上的错误计算、前视、错误成交或契约违背 | 阻塞：同上，低频仍阻塞 |
| P2 | 证实的局限，但当前支持路径不可达或明确超出支持范围 | 留 backlog，本轮不自动修 |
| P3 | 文档漂移或有依据的维护建议 | 留 backlog，本轮不自动修 |

退出码、logger 等级和审查严重级是不同口径。预期涨跌停拒单是交易规则，磨损高是策略
经济性，缺行情是数据完整性；须说明各自影响，不能一律说“报错”，也不能一律忽略。

## findings 格式

```yaml
meta:
  date: 2026-10-12
  commit: c97f19e
  scope: "关键计算链路与门禁；覆盖与限制见审查记录"
findings:
  - id: F-EXAMPLE-01
    severity: P1
    rule: "AGENTS.md 设计契约：T+1 锁定"
    file: btcore/engine.py
    line: 1
    note: "触发输入；复现命令或测试；实际值；独立期望值及公式；影响对象"
```

示例位置是占位值。`id/severity/rule/file/line/note` 必填，file 为相对仓库根的真实文件。
脚本机械检查结构；不会执行复现，也不会判断影响是否属实，agent 必须核实证据。

## 有限流程

1. 完成约定范围的审查，写记录与 findings。
2. `python scripts/review_gate.py check <findings.yaml> --scope full|diff`。
   - exit 1：存在未决 P0/P1，包括历史未决；必须明确报告阻塞。
   - exit 0：发现门禁通过；P2/P3 入 backlog，不因此追加检查轮次。
   - exit 2：输入非法或 full 冷却期内；不更新 backlog，不产生审查通过结论。
3. 若用户请求修复，先用独立期望值建立回归用例，再最小修复。审查请求本身不等于授权
   启动所有金融逻辑修复、参数调整、重构或依赖升级。
4. 修复后验收直接影响的 diff，通过后 `close <ID>`；只有用户明确决定接受风险时才
   `close <ID> --waive "<用户决定与原因>"`。不得伪造用户 waive。
5. 范围已完成且无未决 P0/P1，即终止审查并进入相应 done-bar。P2/P3 不阻碍终止。

不再要求“连续两轮无新增”。重复提交同一 findings 不算独立审查；脚本的 CONVERGED
仅表示登记项没有未决阻塞，不证明范围覆盖、复现、计算正确或实盘可用。
同一问题两次修复仍失败，停止自动改动，报告复现和失败原因。没有新 diff、失败测试、
新复现或用户扩大范围，不得继续检查循环。新复现的 P0/P1 始终必须报告。

## ID、backlog 与冷却

`docs/review_backlog.yaml` 由脚本维护；open 为未决项，closed 为修复或 waive 记录。

- 同一 open ID 内容不变：跳过；有新证据或分级变化：更新同一项，保留 opened 日期。
- closed ID 内容不变：跳过；有新证据的实质变化：重新 open。
- 换措辞、挪行号不是复发证据；agent 不得仅凭这些原因重开。
- `--scope full` 最近 14 天内再用会返回 exit 2；修复验收用 diff。
- 脚本仅有仓库级 `last_full_audit`，不支持按子系统分别计冷却。超过 60 天的 HINT
  是信息提示，不是授权或验收要求。
- 查看：`python scripts/review_gate.py backlog [--closed]`。

## 三层验收

### 自动检查

必须有反破坏、skill 同步、Ruff 与全量 pytest 的实际输出，并记录跳过与失败项。

```bash
python scripts/review_gate.py done --full
ruff check btcore/ tests/ scripts/ research/ strategies/ factors/ adapters/
```

`done` 先检查未决 P0/P1，然后运行反破坏与 skill 同步；`--full` 才运行测试。
未加 --full 时明确打印“测试未执行”。两种调用都不自动执行真实库或实盘检查；
返回 0 只表示这次实际执行的自动检查通过，不能声称完整 done-bar 通过。
阻塞存在时 done 返回 1；可以单独运行 pytest 等收集证据，不能绕过阻塞认证。

### 计算检查

资金、撮合、公司行为、统计或因子时序变动须增加与改动相称的独立证据：手算小案例、
原始数据重建现金/持股/市值/费用、受影响指标对照。时序变更加未来扰动或截断检验。
记录策略配置、数据路径/窗口/快照信息、误差容忍值；解释新旧数值变化和历史结果影响。
固定样本通过不推广为所有策略、日期或数据源通过。

`cross_validate` 是行为与经济性筛查，不能覆盖所有会计计算、成交边界和前视检查；
退出码非零要解释问题类型，不能靠改阈值或静音换取绿色输出。

### 实盘检查

有成交和券商现金/持股快照一致的已有对账证据，或在账本副本执行验证。
没有真实券商快照时写“未验证”。不得为审查执行真实 sync 写账，不改生产策略、
研究基线或真实成交记录。fixtures parity 只能证明测试覆盖的实现路径一致。

完整 done-bar 需三层证据与零未决阻塞；单层通过不替代其余层。报告分别说明自动检查、
计算抽样、真实实盘证据及未验证范围，不承诺“全部正确”或“零风险”。
