# 实盘账本操作

先读[流程与写入边界](../../../docs/live_guide.md#workflow)。确认账本路径、日期、
券商输入和用户已有授权；研究/排错在副本执行。init、sync、signal 均可能写账，
signal 不是只读查询；skill 不授予写真实账本或券商下单权限。

## 每日操作

1. 确认行情、分红和日历覆盖对账日。
2. 按[输入格式](../../../docs/live_guide.md#input)准备全量现金/持仓和实际成交，执行 sync。
3. 核对 ok/stage、持仓差异、现金 ADJUST 与告警；失败先定位，不能手改持仓凑平。
4. 对账通过后执行 signal，读取[操作单语义](../../../docs/live_guide.md#operations)。
   买入数量是估算，券商条件的优先级/撤单需由实际交易流程保证。
5. 保存实际成交，下一日对账；未成交不记为成交，条件单每日核对。

## 不可混淆的账本语义

- ledger_fills 为手工成交来源，其他持仓/现金由回放衍生；公司行为自动计算，勿重复录入。
- sync 幂等只去完全重复成交，不能证明缺失成交已补齐。
- statement 非开市日会归一；显式 fill 日期必须本身合法，不会自动归一兜底。
- reason 消费于冷却期、归因和 ML 标签，应如实对应触发来源。
- 仅支持当前后端覆盖的 A 股个股；ETF/基金缺行情不等于零持仓。

排错按[错误阶段表](../../../docs/live_guide.md#troubleshooting)检查输入和原始记录。
真实账本修复须可追溯并在授权范围内；不要直接修改衍生表或为通过对账静音告警。

## 验证与停止

[E2E 回放](../../../docs/live_guide.md#verification)要求 --bt-db；--ledger 必须在专用空目录。
脚本会删除该路径及同目录 test_b.duckdb，绝不能使用真实账本路径。
确认末日 pending 等适用限制；回测往返一致不替代券商快照。

交付处理日期、对账差异/调整、操作单路径与未验证范围。遇到缺成交或源数据矛盾，
停止依赖该错误状态的写入并明确所需证据，不反复改账尝试直到通过。
